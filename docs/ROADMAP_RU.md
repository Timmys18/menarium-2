## Что сделано в продукте

### Пользовательские потоки

- Регистрация и вход (credentials + NextAuth)
- Каталог: поиск, категории, города, тип, сортировка (новые / тренды / популярные по числу предложений обмена)
- Свайп: исключение своих объявлений, уже предложенных обменов и пропущенных карточек (`SwipePass`)
- Создание и редактирование объявлений с фото
- Карточка объявления: галерея, предложение обмена, чат по объявлению
- Обмен: вкладки входящие / исходящие / совпадения, действия по статусам, чат сделки
- Профиль: статистика, быстрые ссылки, редактирование, выход
- Уведомления с отметкой прочитанного
- Админ-модерация по `ADMIN_EMAILS`

### Технический контур

- Prisma 6 + PostgreSQL, миграции `0001_initial`, `0002_swipe_pass`
- Redis rate limits (опционально в dev)
- S3 или локальный `/uploads`
- Global loading / error / not-found
- Редиректы `/profile/my-swaps` и `/swaps` → `/exchange`

## Завтрашний план (ваши действия)

1. Выбрать хостинг (VPS или PaaS в РФ/допустимой юрисдикции).
2. Поднять PostgreSQL, Redis, S3-совместимое хранилище.
3. Скопировать `.env.production.example` → production env, сгенерировать `NEXTAUTH_SECRET`.
4. DNS `menarium.ru` / `www` → сервер, HTTPS (Certbot или платформа).
5. На сервере: `npm ci` → `db:deploy` → `build` → PM2/Docker.
6. Пройти `docs/PRODUCTION_CHECKLIST.md` (ручной smoke).
7. **Не** использовать demo-пароли seed в production.

## Риски и ограничения

- Рейтинг пользователей в UI убран до появления реальной модели отзывов.
- Next.js 16 предупреждает о переименовании `middleware` → `proxy`; на работу не влияет.
- `npm audit fix --force` не применять — зависимости зафиксированы overrides в `package.json`.
- Ночная сборка на слабой RAM: использовать `node --max-old-space-size=4096` (уже в `build` script).
