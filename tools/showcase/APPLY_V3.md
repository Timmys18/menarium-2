# Как поднять вариант 3 из этого репозитория

В репозитории лежит вариант 1 — то, что вы видите в `src/`. Варианты 2 и 3
не отдельные ветки, а надстройки над ним: у них общий код, различается
оформление. Вариант 3 приложен здесь патчем.

```bash
# рядом с репозиторием, не поверх него
cp -r . ../menarium-v3
cd ../menarium-v3
patch -p1 < tools/showcase/v3.patch
node tools/showcase/icons.mjs      # знаки пересобираются из вектора
```

`icons.mjs` нужен потому, что три растровых знака (иконка приложения,
apple-icon, знак на карточке для соцсетей) в патч не входят — двоичные файлы
в текстовом diff бесполезны. Они полностью выводятся из
`public/brand/menarium-exchange.svg`, который патч меняет.

Дальше — своё окружение и сборка:

```bash
cp ../menarium-2/.env .env        # и поправить порт, базу, индекс Redis
tools/showcase/prepare.sh $(pwd)  # миграции, сид, боевая сборка
```

## Эталоны для визуальных тестов

Патч не содержит снимков `e2e/**-snapshots/`: у варианта 3 другое
оформление, поэтому эталоны варианта 1 ему не подходят по определению.
Их нужно перевыпустить один раз:

```bash
tools/showcase/e2e-v3.sh --update-snapshots
tools/showcase/e2e-v3.sh                    # проверить, что они устойчивы
```

Второй прогон обязателен. `--update-snapshots` записывает эталон по тому
кадру, который получился, — включая случайно неудачный. Только следующий
прогон, уже без ключа, доказывает, что эталон воспроизводится.

## Почему отдельный скрипт для прогона

`npm run test:e2e` внутри проекта берёт `DATABASE_URL` из его же `.env` — то
есть бьёт по базе, которую в этот момент отдаёт витрина. Набор её пересевает
и меняет пароли (в нём есть сценарий восстановления пароля), после чего в
витрину перестаёт пускать. `e2e-v3.sh` уводит прогон на отдельную базу и
отдельный индекс Redis и заодно убеждается, что порт 3001 свободен: иначе
тесты молча отработают по чужой сборке и чужим данным.
