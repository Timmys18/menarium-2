# Три витрины Менариума

Три независимых боевых сборки продукта, по одной на вариант дизайна. Каждая —
отдельный проект со своей базой, своим Redis и своим портом. Их можно держать
поднятыми одновременно и ходить между вкладками, сравнивая одно и то же
действие в трёх оформлениях.

| Вариант | Адрес                  | База          | Redis | Каталог          |
|---------|------------------------|---------------|-------|------------------|
| v1      | http://localhost:3101  | `menarium_v1` | БД 1  | `../menarium-v1` |
| v2      | http://localhost:3102  | `menarium_v2` | БД 2  | `../menarium-v2` |
| v3      | http://localhost:3103  | `menarium_v3` | БД 3  | `../menarium-v3` |

Каталоги вариантов лежат рядом с репозиторием. Скрипты выводят пути сами —
`REPO` из своего расположения, `VARIANTS` как родительский каталог, — но и то
и другое можно задать переменными окружения, как и `LOGS` (по умолчанию
`/tmp/menarium-showcase`: логи витрин не должны оседать в репозитории).
Вариант 1 — это сам репозиторий; как получить из него вариант 3, описано в
`APPLY_V3.md`.

## Управление

```bash
tools/showcase/menarium.sh up        # поднять службы и все три
tools/showcase/menarium.sh status    # что живо
tools/showcase/menarium.sh down      # остановить
tools/showcase/menarium.sh build v2  # пересобрать один вариант
tools/showcase/menarium.sh logs v3   # хвост лога
```

`up` идемпотентен: повторный запуск не плодит процессы, а сначала освобождает
порты. PostgreSQL поднимается через `pg_ctl` от пользователя `postgres`,
поэтому переживает завершение оболочки — `embedded-postgres` этого не умеет и
умирает вместе с родительским процессом.

## Приёмочный набор

```bash
tools/showcase/e2e-v3.sh                      # весь набор для v3
tools/showcase/e2e-v3.sh e2e/chat-media.spec.ts
```

Отдельный скрипт нужен по одной причине: `npm run test:e2e` внутри проекта
берёт `DATABASE_URL` из его же `.env` и бьёт по `menarium_v3` — той самой базе,
которую в этот момент отдаёт витрина на 3103. Набор её пересевает и меняет
пароли (в нём есть сценарий восстановления пароля), после чего в витрину
перестаёт пускать, а сам прогон ловит чужие соединения и начинает мигать.
Скрипт уводит прогон на `menarium_v3_e2e` и Redis БД 9, убеждается, что порт
3001 свободен (иначе тесты молча отработают по чужой сборке), и останавливает
витрину v3 на 3103.

Последнее — не перестраховка. Витрина и сервер тестов раскладывают статику в
один и тот же каталог `<проект>/.next/standalone/.next/static`: оба сначала
стирают его, потом копируют заново. Работая одновременно, они вырывают чанки
друг у друга, и живой сервер отдаёт `ChunkLoadError` на случайных переходах.
Со стороны это выглядит как «тест иногда подвисает»: приёмочная матрица
падала по таймауту в 300 секунд то на одном разрешении, то на другом, и
проходила с повтора. Причина нашлась только в логе браузера —
`ChunkLoadError` на чанке, которого уже не было на диске. С остановкой
витрины тот же файл проходит 4 из 4 за 2,7 минуты вместо таймаута.

## Входы

Одинаковые во всех трёх (базы засеяны одним сидом):

- `maria@menarium.ru` / `MenariumDemo2026!`
- `dmitry@menarium.ru` / `MenariumDemo2026!` — второй участник для обмена
- `admin@menarium.ru` / `MenariumAdmin2026!` — админ-панель

Базы разные, поэтому действия в одной витрине не видны в других: можно смело
создавать объявления и обмены в каждой.

## Что именно различается

**v1 — убрать лишнее.** Палитра, шрифт и размеры не тронуты. Градиент остался
только на главном действии; в четырнадцати других местах (шапка, поиск,
пагинация, выбранные вкладки, плашки категорий) он заменён либо тихой
вторичной кнопкой, либо подсветкой акцентом. Рамки внутри карточек убраны —
«Ищу взамен», «В обмен рассматривает» и блок предложения обмена отделены
воздухом и волосяной линией.

**v2 — дать характер.** Всё из v1, плюс: заголовки страниц набирают вес (650 →
800) и плотность (-0.045 → -0.055em), вспомогательный текст, наоборот,
облегчается до 300 — контраст строится весом, а не только размером. Главная
кнопка становится сплошной бирюзой вместо градиента. Поля ввода и выпадающие
списки — подчёркивание вместо коробки, отчего на экране заметно меньше линий.

**v3 — полная переработка.** Всё из v2, плюс своя материя и своя композиция.

*Материя.* Тёмно-синий уходит в тёплый уголь (`#0c0b0a`), акцент — терракота
(`#e86a3d`) вместо бирюзы, фон перестаёт светиться двумя цветными пятнами,
карточки держатся тенью, а не обводкой. Светлая тема — не инверсия, а бумага
(`#faf7f3`) с притемнённым акцентом. Знак в шапке перекрашен из синего в
терракоту прямо в векторе, с сохранением порядка светлот внутри фаски,
поэтому объём читается как в исходном; из него же пересобраны иконка
приложения, apple-icon и знак на карточке для соцсетей. `theme_color`
манифеста, цвет вкладки браузера и автономная страница ошибки переведены
туда же — иначе продукт выдавал прежнюю палитру там, где до CSS дело не
доходит.

*Композиция.* На странице товара заголовок выходит из карточки на всю полосу
и фотография становится главной. Свайп разложен на две колонки — колода
слева, слово справа; колода веером вправо (симметричный упирался в край
страницы), три круглые кнопки вместо сплошного дока, подсказка «можно тянуть»
убрана, потому что стопка карт объясняет жест сама. Акцент в заголовке —
контраст веса 800↔200 внутри одного Onest, а не второй цвет; градиентные
надписи убраны вместе с четырьмя мёртвыми правилами, которые их держали.

*Ярусы.* Восемь надзаголовков были набраны синим «информационным» цветом —
декоративно, не по смыслу. Теперь у них собственный тихий ярус под
терракотовым надзаголовком страницы: три уровня сведений перестали выглядеть
одинаково.

*Полоса.* Ширина полосы была случайной — shell, 7xl, 6xl, 5xl, 1360px, семь
значений на тринадцать страниц. При переходе каталог → уведомления страница
прыгала вбок на 184 пикселя. Обзорные страницы сведены к одной полосе;
узкими остались только соглашения (длина строки для чтения) и формы.

Отдельная деталь: одной смены токенов для v3 не хватило. В разметке 179 мест
обращаются к цвету напрямую (`bg-teal-300/10`, `border-blue-400/25`), и они
токенам не подчиняются — интерфейс оставался наполовину сине-зелёным. Вместо
179 правок переопределены значения самих оттенков Tailwind: тёплый ряд
подставляется всюду, где был холодный.

## Честные оговорки

- **Это витрины, а не прод.** `APP_ENVIRONMENT=ci` выставлен намеренно: иначе
  срабатывает защита, которая в боевом окружении блокирует демо-фотографии,
  и все карточки остались бы без картинок. Сборка при этом настоящая
  production (`NODE_ENV=production`, standalone). Тестовые лазейки закрыты:
  `E2E_TEST_MODE` не выставлен, служебный маршрут сброса лимитов отвечает 404.
- **Секреты в `.env` — локальные.** `NEXTAUTH_SECRET` и Sentry DSN
  плейсхолдерные, для настоящего деплоя их нужно заменить. `.env` в gitignore.
- **`node_modules` общий** — три копии связаны жёсткими ссылками с
  репозиторием (`cp -al`), поэтому занимают ~1 ГБ на всех, а не 3.6 ГБ. Если
  понадобится разойтись по версиям зависимостей, копии нужно будет расцепить.
- **Не проверено на живом устройстве.** Всё измерено в headless-Chromium на
  одной машине. Реальный телефон — с его безопасными зонами, полосой адреса
  и настоящим касанием — не проверялся ни в одном варианте.
